# V22 internet research and decision record

Reviewed October 29, 2026, IST. Technical conclusions use primary papers, author repositories and official documentation. Local data and saved predictions were inspected locally; restaurant rows were not sent to an inference API. No weights, packages, GPU session or new turnover estimator were acquired for this proposal.

## Evaluation and data-shift evidence

| Primary source | What it supports | V22 decision and limit |
|---|---|---|
| [Cawley & Talbot, JMLR 2010](https://jmlr.org/papers/v11/cawley10a.html) | A finite-sample model-selection criterion can itself be overfit; selection affects subsequent evaluation. | Restrict V22 to one component and three weights. Reusing labels across new partitions does not erase the prior search. |
| [scikit-learn: nested versus non-nested validation](https://scikit-learn.org/stable/auto_examples/model_selection/plot_nested_cross_validation_iris.html) | Tuning and evaluation have different roles; selection on evaluation data biases measured performance. | No fitting a meta-model or choosing weights on all cached OOF labels and reporting that same fit as new validation. Ordinary locked blending needs no learned meta-model. |
| [Sugiyama et al., JMLR 2007](https://www.jmlr.org/papers/v8/sugiyama07a.html) | Importance-weighted validation addresses a specific setting: different feature distributions with an unchanged conditional target distribution. | Domain classification does not establish that setting. Do not infer a new target distribution, replace ordinary RMSE, or automatically rerun V6 weighting. Clipping weights introduces an additional bias/variance choice. |
| [Zhou, Balakrishnan & Lipton, AISTATS 2023](https://proceedings.mlr.press/v206/zhou23b.html) | Missingness mechanisms can differ across domains; identification and adjustment depend on observed indicators and assumptions. | Counts alone do not justify imputing training to look like test or interpreting zero Zomato as missing. The theory is not a dataset-specific correction. |
| [Rockenschaub et al., 2024 author preprint](https://arxiv.org/abs/2406.16484) | Prediction under missingness shift depends on whether the shift is ignorable; real estimators can have different robustness. | Keep incidental missingness as a documented issue. Its weak domain-classification signal does not warrant another V22 branch or establish that missingness is harmless. |
| [Wu et al., ICML 2019](https://proceedings.mlr.press/v97/wu19f.html) | Aligning domain representations can fail when the assumptions connecting labels across domains do not hold. | Reduced domain AUC is an investigative lead, not a turnover accuracy objective or proof of label preservation. Avoid blind test-mean or quantile matching. |
| [Gulrajani & Hashimoto, ICML 2022](https://proceedings.mlr.press/v162/gulrajani22a/gulrajani22a.pdf) | Multiple distribution-aligning maps may be possible, with different implications for labels; identifiability needs extra structure. | Do not subtract the observed survey-score mean differences from test values and call it a repair. |
| [scikit-learn: permutation importance](https://scikit-learn.org/stable/modules/permutation_importance.html) | Held-out performance changes measure fitted-model reliance; correlated features complicate interpretation. | Feature importance would be a diagnostic, not evidence that a shifted feature is invalid. V22 instead tests a predeclared pair ablation with ordinary held-out RMSE. |
| [scikit-learn: ROC AUC](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.roc_auc_score.html) | ROC AUC measures ranking performance for domain labels in this diagnostic. | The saved AUCs concern train/test membership, never restaurant turnover or expected leaderboard gain. |

## Current model options checked against official sources

| Primary source | Verified capability or constraint | Priority for this dataset |
|---|---|---|
| [Prior Labs TabPFN repository](https://github.com/PriorLabs/TabPFN), [3.5 technical report](https://arxiv.org/abs/2609.17895) | Current 3.5 implementation/report, regression support, missing values, version-specific models and fitted-state persistence. The current README describes defaults that can evolve. | Keep the exact already-successful V14 3.5 checkpoint. Broad benchmark results do not imply a restaurant-specific gain from another variant. Do not upgrade its environment while testing a feature ablation. |
| [Prior Labs extensions](https://github.com/PriorLabs/tabpfn-extensions) | Feature-selection/interpretability, unsupervised imputation/outlier detection and other extensions exist; the repository labels them experimental. | These are possible research tools, not evidence to delete hard labels or launch an adaptive feature search on exhausted validation labels. No extension is needed for the fixed two-column projection. |
| [LimiX official repository](https://github.com/limix-ldm-ai/LimiX), [LimiX-2 paper](https://arxiv.org/abs/2609.17488), [architecture router](https://raw.githubusercontent.com/limix-ldm-ai/LimiX/main/inference/predictor.py), [v2 predictor](https://raw.githubusercontent.com/limix-ldm-ai/LimiX/main/inference/v2_0/predictor.py) | Regression is supported. The factory dispatches by checkpoint architecture; v2 expects its own configuration structure. Current installation describes flash-attn installation as optional, and the public CLI exposes CPU as well as CUDA. | Do **not** call every LimiX path T4-incompatible. LimiX-2 and LimiX-2M are different identities. Exact checkpoint, attention behavior, train-only preprocessing, query independence, memory and fitted-state behavior remain unmeasured here. Promising author benchmarks do not settle those questions or restaurant accuracy. Lower priority than the cheap controlled P35 test. |
| [Google Research TabFM](https://github.com/google-research/tabfm) | Regression wrapper; documented defaults of 500 features and **100 context rows**, with sampled contexts for larger tables. | A default run is not a full-context comparison on all 3,493 labels. An explicitly designed sampling/context study could be legitimate, but it would introduce another hypothesis and engineering burden. Defer from V22. |
| [TabSTAR official repository](https://github.com/alanarazi7/TabSTAR) | Regression and v1.1 alternatives exist; its stated focus is tabular data with text fields. | The restaurant categories are short labels rather than rich descriptions. A text-specific advantage here is uncertain; this is an inference from the schema, not an accuracy result. Do not describe it as tested or failed. |
| [TabSwift author paper](https://arxiv.org/abs/2606.07345) | Regression support and efficient row-wise attention, with comparisons against earlier foundation-model baselines. | Efficiency is useful but is not a demonstrated advantage over the exact V14 3.5 ensemble. Defer another integration. |
| [Official Colab FAQ](https://research.google.com/colaboratory/faq.html) | Free GPU allocation, hardware and runtime duration are variable. | Four hours is an operational ceiling and needs a measured feasibility forecast; it is not a guaranteed allocation. |

Current online source branches are research evidence, not immutable execution pins. V22 reuses the already-pinned V14 computational identity. If a later experiment chooses another family, it must separately lock source and checkpoint revisions and verify downloaded bytes before accuracy testing.

Some attempted documentation links and guessed LimiX attention/configuration paths returned access errors or 404. They supplied no supporting evidence. In particular, no T4 compatibility conclusion is drawn from a missing page. The successful official README/router/predictor pages support only the narrower statements above.

**Decision:** one fixed P35-SC38 component and three blends are justified as a bounded falsification attempt. No source guarantees a better score. If it fails, preserve V14 and require new documented data information before another campaign expansion.
